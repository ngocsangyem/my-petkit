## Three kinds of hardware

How you connect a device depends on what is inside it, not on whether it is a litter box or a feeder.

| Family | Models | How it reaches MyPetKit |
|---|---|---|
| Embedded Linux, with camera | T5, T6, T7, D4H, D4SH (Ingenic MIPS), W7H (ARM) | Bluetooth provisioning only. They insist on HTTPS, so a DNS redirect is not enough. MQTT needs a [patcher](/docs/firmware). |
| ESP32 | T3, T4, D3, D4, D4S, Feeder, Feeder Mini | Bluetooth provisioning, or a DNS redirect, since they talk plain HTTP. They must reach the server on port 80. |
| Bluetooth only | W4, W5, CTW2, CTW3, K2, K3 | Through a parent: a mains-powered litter box or feeder that relays for them. |

The Feeder and Feeder Mini have no Bluetooth radio, so only a DNS redirect can reach them. Their signup carries no id and no serial, so a factory-fresh unit may be refused. Nobody has run one.

## Bluetooth-only accessories

A fountain or spray with no Wi-Fi reports through a parent within range. Pair it from the panel of the device that will relay for it. The parent does not discover anything on its own: it asks the cloud what to scan for. That scan number has been read from a real pairing for the W5 and the CTW3 only. For the other models it is borrowed from their product line, so if an accessory never reports, change **Scan type** under Advanced first.

With no parent device at all, MyPetKit cannot reach a fountain. [aavdberg/ha-petkit](https://github.com/aavdberg/ha-petkit) talks to these models over Bluetooth from Home Assistant directly.

## A model that is not listed

Turn on proxy mode (dashboard, Settings). Every request is then forwarded to PetKit as well, so the device keeps behaving normally while everything it says is recorded. That recording is what is needed to add the model. See [Contributing](/docs/contributing).
