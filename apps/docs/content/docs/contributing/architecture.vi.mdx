## Các package

```text
my_petkit/
├── main/          process lifecycle: cli -> wiring -> lifecycle
├── config.py      every setting, from /data/options.json, the Supervisor, the CLI and the panel
├── http/          the cloud a device believes it is talking to
│   ├── server.py      route table, and the catch-all that must stay last
│   ├── handlers/      one module per endpoint
│   ├── middleware/    device identity, proxy forwarding, request logging
│   ├── redact/        what a cloud reply is allowed to contain
│   ├── bucket.py      the unauthenticated media upload sink
│   └── cloud_fetch.py signs as the device to ask PetKit something directly
├── mqtt/          broker (amqtt), Aliyun HMAC auth, topics, bridge, BLE relay, upstream
├── devices/       Device identity and state, response payloads, registry, state parsers, BLE
├── ha/            device category -> entities, discovery, publisher, command router
├── events/        codes.py (the protocol tables), decode, normalize, sessions, store
├── media/         decrypt -> remux -> path -> row, chunk stitching, retention, go2rtc
├── features/      the user plane, one package per feature; features never import each other
├── shared/        what several features need
├── web/           composition root: the app and the whole route table; serves apps/web
├── patchers/      on-device patches: cacert, mqtt, cloud, camera, ssh, talk, pan
├── ai/pets.py     pets and the face photos the device matches against
└── utils/         constants, crypto, capture, JSON I/O, paths, coercion, clock
```

`devices` chỉ phụ thuộc vào `events` và `utils`; nó không biết Home Assistant tồn tại. Câu hỏi "thiết bị này công bố những thực thể nào" được trả lời trong `ha/categories.py`.

## Một yêu cầu qua HTTP

Bốn middleware bao quanh mọi yêu cầu, từ ngoài vào trong:

```text
device --HTTP--> http/server.py          /{path:.*} is registered LAST, so an
                   │                     unknown endpoint is answered, never 404'd
                   ├─ never_fail         no failure of ours reaches the device as a 5xx
                   ├─ logging            live log, capture file, online/last_seen
                   ├─ device             X-Device + URL -> device_type, ...
                   └─ proxy              off: call the handler, return its answer
                        │                on:  call the handler FIRST and keep its answer,
                        │                     then forward; PetKit's reply is used only if
                        │                     it is usable and survives http/redact/
                        └─> handlers/<endpoint>.py
                              └─> devices/payloads.py builds the body the firmware expects
```

Handler cục bộ vẫn chạy ngay cả ở chế độ proxy. Nhờ vậy việc "PetKit không truy cập được, chậm, hoặc từ chối thiết bị này" không còn là chuyện đáng lo.

Một lệnh cho thiết bị đang dùng HTTP chờ trong `Device.command_queue` cho đến khi thiết bị thăm dò `dev_heartbeat` và nhận lệnh trong phản hồi.

## Một frame qua MQTT

```text
device --MQTT--> mqtt/broker.py (amqtt)
                   ├─ mqtt/auth.py    HMAC on CONNECT, and it subscribes the device itself,
                   │                  because a T5 sends no SUBSCRIBE of its own
                   └─ mqtt/bridge.py  one `#` subscription, dispatching each frame to
                          ├─> devices/state_parsers.py -> device.state
                          ├─> events/normalize.py -> events/store.py
                          └─> ha/publisher.py -> Home Assistant
```

Một subscription `#` bao phủ mọi thiết bị, nên bất cứ lỗi nào lọt qua khâu xử lý từng thông điệp sẽ làm sập cầu nối cho tất cả thiết bị.

## Một lệnh từ Home Assistant

```text
HA's broker --MQTT--> ha/publisher.py     subscribes my-petkit/+/cmd/+
                        └─> ha/command_router.py
                              └─> ha/commands.py builds the device command
                                    ├─ device.mqtt_connected?  published over MQTT
                                    └─ otherwise               queued for the next heartbeat
```

`Device.mqtt_connected` chọn phương thức truyền, và phương thức truyền không có báo cáo giao nhận. Publish tới một topic không ai subscribe không ném lỗi gì, nên một giá trị `True` đã cũ sẽ nuốt lệnh một cách lặng lẽ.

## Tri thức về giao thức nằm ở đâu

- `events/codes.py`: mọi mã sự kiện, trong bảy namespace không bao giờ được gộp. Mỗi dòng được chấm theo bằng chứng và ghi rõ hàm firmware mà nó đến từ.
- `devices/payloads.py`: các phần thân phản hồi. Một giá trị bịa ra ở đây sẽ được phục vụ cho thiết bị như cài đặt của chủ nhân, đó là lý do nhiều trường được cố ý để trống.

Cả hai đều lớn có chủ đích. Hãy đọc `AGENTS.md` trước khi thay đổi bất kỳ tệp nào.
